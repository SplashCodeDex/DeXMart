## Overview (After Understanding the Distinction)
Conductor is a Gemini CLI extension that enables Context-Driven Development. It helps you specify, plan, and implement software features and bug fixes through a structured workflow.

Once you're inside Gemini CLI, Conductor provides:
- Project context persistence via Markdown files
- Structured workflow: Context → Spec & Plan → Implement
- Track-based organization for features/bugs
- Built-in review and progress tracking mechanisms

## Key Commands (To Be Run in Gemini CLI)

### 1. Project Setup (Run Once Per Project)
```
/conductor:setup
```
Initializes the Conductor environment and creates core context files in the `conductor/` directory:
- `conductor/product.md` - Product goals and high-level features
- `conductor/product-guidelines.md` - Standards (prose style, brand messaging, etc.)
- `conductor/tech-stack.md` - Technology choices and constraints
- `conductor/workflow.md` - Workflow preferences and rules

### 2. Creating Work Tracks
```
/conductor:newTrack
```
Creates a new track directory for a feature or bug fix containing:
- `spec.md` - Detailed specification of what to build
- `plan.md` - Task-oriented plan broken into phases and subtasks
- `metadata.json` - Track metadata

### 3. Implementation
```
/conductor:implement
```
Executes tasks from the current track's plan. The Conductor agent:
- Reads `plan.md`
- Updates progress in the track's metadata
- Supports optional `--ralph` flag for Ralph loop technique

### 4. Progress Tracking
```
/conductor:status
```
Displays current progress across all tracks

### 5. Review Process
```
/conductor:review
```
Reviews completed work against guidelines and the plan by reading:
- `plan.md`
- `product-guidelines.md`

### 6. Reverting Work
```
/conductor:revert
```
Reverts a track, phase, or task by analyzing git history

## Usage Workflow

1. **Initialize** (if not already done):
   ```
   /conductor:setup
   ```

2. **For each new feature/bug**:
   ```
   /conductor:newTrack
   ```
   - Edit the generated `spec.md` to define requirements
   - Edit the generated `plan.md` to outline implementation steps
   - Review the spec and plan

3. **Implement**:
   ```
   /conductor:implement
   ```
   - The agent executes tasks according to the plan
   - Progress is tracked automatically

4. **Review**:
   ```
   /conductor:review
   ```
   - Verify implementation meets specifications and guidelines

5. **Iterate** as needed, then move to next track

## DeXMart Specific Considerations

When using Conductor with the DeXMart monorepo:

1. **Context Files Location**: Conductor will create a `conductor/` directory at the repository root

2. **Multi-Package Awareness**: Be sure to specify which package (frontend, backend, openclaw, shared) your work targets in the spec and plan

3. **Technology Stack Documentation**: When running `/conductor:setup`, document DeXMart's specific stack:
   - Frontend: Next.js 16, React 19, Tailwind CSS 4, Zustand 5
   - Backend: Express 5, Node.js 24-25, Firestore, Gemini AI
   - Shared: TypeScript monorepo with pnpm workspaces

4. **Workflow Preferences**: Document DeXMart's development practices:
   - TDD mandate (Red → Green → Refactor)
   - Zero warnings ESLint policy
   - Layered architecture (Routes → Controllers → Services → Database)
   - Tenant-scoped operations

## Troubleshooting

- If commands aren't recognized, ensure you're in a Gemini CLI session
- Verify extension is installed: `gemini extensions list` should show "conductor"
- For installation issues, try: `gemini extensions uninstall conductor` then reinstall
